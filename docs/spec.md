# ブラウザで学ぶ SQL 入門編の仕様

[マップ](../.scratch/sql-learning-site/map.md)の 9 枚のチケットで決めたことを、実装に渡すために 1 つにまとめた文書である。
各決定の理由は、節の末尾に挙げたチケットにある。
マップ、チケット、調査結果、試作は手元の作業メモ（`.scratch/`）に置いており、リポジトリには含めていない。
用語は [CONTEXT.md](../CONTEXT.md) に従う（学習者、レベル、レッスン、例、演習、模範解答、期待結果、題材データ、進捗、修了、総まとめ、ローカル環境）。

## 目的と範囲

SQL を一度も書いたことがない学習者（非エンジニアを含む）が、ブラウザだけで SQL を書いて実行しながら学べるサイトを作る。
サイト名は「ブラウザで学ぶ SQL」である。
サーバーもログインも使わず、静的サイトとして GitHub Pages で公開する。
PC で使うことを前提にし、スマホではレッスンを読めてレイアウトが崩れない程度にとどめる。

今回作るのは入門編である。
サイトの骨組みは 4 レベルを前提に作るが、中身を作るのは入門だけである。
入門は 1 レッスン 10〜15 分で 10 レッスン、合計 2 時間前後の量にする。

次の作業は対象外とする。

- 初級、中級、実践応用の中身（境界の 1 行を除く）。
- ログインと、サーバー側での進捗の保存。
- スマホでの演習。
- 自由に SQL を試す遊び場のページ、アクセス解析、修了証、進捗を消すボタン。

## 4 レベルの構成

| レベル | 境界 |
|---|---|
| 入門 | 1 つのテーブルから、条件に合う行と必要な列を取り出して並べる（`SELECT` のみ） |
| 初級 | 複数のテーブルを結合し、集計し、データを変更する |
| 中級 | サブクエリやウィンドウ関数を使い、複雑な問いを 1 つのクエリで書く |
| 実践応用 | Docker で用意したローカル環境の PostgreSQL で、テーブル設計、インデックス、トランザクション、実務の課題に取り組む |

構文の割り当ては次のとおりである。

- **入門**：`SELECT`、`FROM`、`WHERE`（比較、`AND`、`OR`、`NOT`）、`LIKE`、`IN`、`BETWEEN`、`NULL` と `IS NULL`、`ORDER BY`、`LIMIT` と `OFFSET`、算術演算と `AS`、`DISTINCT`
- **初級**：`JOIN`（`LEFT JOIN` で NULL を再び扱う）、集約関数、`GROUP BY`、`HAVING`、`INSERT`、`UPDATE`、`DELETE`
- **中級**：サブクエリ、`CASE`、`WITH`、`UNION`、文字列と日付の関数、ウィンドウ関数
- **実践応用**：`CREATE TABLE`、型、制約、正規化、インデックスと `EXPLAIN`、トランザクション、知識を組み合わせる実務的な課題

入門から中級まではブラウザの中で SQL を実行し、実践応用だけローカル環境を使う。
PGlite は同時に 1 つの接続しか持てず、2 つのセッションでトランザクションの分離を見せられないからである。

出典：[4 レベルの境界](../.scratch/sql-learning-site/issues/03-level-boundaries.md)

## 入門カリキュラム

| # | ファイル名 | レッスン名 | 構文 | 到達目標 | つまずきどころ |
|---|---|---|---|---|---|
| 1 | `01-first-select` | はじめての SQL | `SELECT *`、`FROM` | テーブルの全データを表示できる。テーブル、行、列という言葉がわかる | |
| 2 | `02-columns` | 列を選ぶ | `SELECT 列, 列` | 必要な列だけを、指定した順に表示できる | 最後の列の後ろの余計なカンマ |
| 3 | `03-where` | 条件で行を絞る | `WHERE`、`=`、`<>`、`<`、`>`、`<=`、`>=` | 数値や文字列の条件に合う行だけを取り出せる | 文字列をダブルクォートで囲むとエラーになる（列名の意味になる） |
| 4 | `04-and-or` | 条件を組み合わせる | `AND`、`OR`、`NOT`、括弧 | 複数の条件を組み合わせて絞れる | `AND` が `OR` より先に評価される |
| 5 | `05-between-in` | 範囲と候補で絞る | `BETWEEN`、`IN` | 範囲や候補の一覧で絞れる | `BETWEEN` は両端の値を含む |
| 6 | `06-like` | 文字の一部で探す | `LIKE`、`%`、`_` | 書名に特定の語を含む本を探せる | `%` を付け忘れると完全一致になる |
| 7 | `07-null` | 値が入っていないデータ | `NULL`、`IS NULL`、`IS NOT NULL` | 値が入っていない行を見つけられる | `= NULL` は 1 行も返さない。`<>` で絞ると NULL の行も消える |
| 8 | `08-order-limit` | 並べ替えて上から取る | `ORDER BY`、`ASC`、`DESC`、複数列、`LIMIT`、`OFFSET` | 並べ替えて上位 N 件を取り出せる | `ORDER BY` なしの `LIMIT` は返る行が決まらない。日本語の書名は `title` では五十音順に並ばない |
| 9 | `09-calc-distinct` | 計算した列と重複の除去 | 算術演算、`AS`、`DISTINCT` | 計算した値に名前を付けて表示できる。重複した行を除ける | 整数どうしの割り算は小数点以下が切り捨てられる |
| 10 | `10-review` | 総まとめ | 1〜9 の構文 | 日本語で書かれた問いを SQL に直せる | |

- **演習の数**：各レッスン 3 問、総まとめは 5 問。1 問目はそのレッスンの構文をそのまま使い、2 問目は少しひねり、3 問目は前のレッスンの構文と組み合わせる。
- **SQL の書き方**：説明と模範解答では、キーワードを大文字にし、文末にセミコロンを付け、句ごとに改行する。小文字でも動くことは第 1 回で伝える。学習者の書き方は採点に影響しない。
- **第 1 回の導入**：データベースが表の集まりであること、テーブル、行、列という言葉、画面の使い方だけを説明し、1 本目のうちに `SELECT * FROM books;` を実行させる。
- **レッスン 8**：`title` で並べると五十音順に崩れる様子を見せ、`title_kana` で並べる方法を教える。

出典：[入門カリキュラム](../.scratch/sql-learning-site/issues/05-intro-curriculum.md)

## 題材データ（入門の版）

入門は `books` テーブル 1 つで完結する。

| 列 | 型 | 意味 |
|---|---|---|
| `id` | integer（主キー） | 本の番号（1〜30） |
| `title` | text | 書名 |
| `title_kana` | text | 書名の読み（ひらがな） |
| `author` | text | 著者名 |
| `genre` | text | ジャンル |
| `price` | integer | 価格（円、税抜） |
| `published_on` | date | 発売日（未定なら NULL） |

- テーブル名と列名は英語にする。日本語にすると、SQL を書くあいだに日本語入力を何度も切り替えることになる。
- 文学は著作権の切れた実在の名作（夏目漱石、芥川龍之介、太宰治、宮沢賢治など）、それ以外のジャンルは架空の本にする。価格と発売日は「この書店が扱う版のもの」とする。
- 題材データはレベルごとに版を分ける。入門の `books` は著者名を文字列で持ち、初級の版で著者を別のテーブルに分ける。

データは 30 冊とし、次の条件を満たす。

- ジャンルは 5 種類程度（小説、技術書、ビジネス、料理、絵本など）。
- 複数の本を持つ著者がいる。
- LIKE で探す語（「猫」など）が複数の書名に含まれる。`_` で探せる短い書名がある。
- ちょうど 1000 円と 2000 円の本がある。
- 発売日未定の本が 2〜3 冊あり、`published_on` が NULL になっている。NULL はこの列だけに入れる。
- 境界にあたる発売日（2024-01-01 など）の本がある。

試作に使った仮のデータが [prototypes/lesson-screen/seed.js](../.scratch/sql-learning-site/prototypes/lesson-screen/seed.js) にあり、上の条件をおおむね満たしている。

出典：[入門の「本」テーブル](../.scratch/sql-learning-site/issues/06-books-table.md)

## 技術構成

| 部品 | 版 | 用途 |
|---|---|---|
| Astro | 7.3.2 | 静的サイトの生成（静的出力、UI フレームワークなし） |
| tailwindcss、@tailwindcss/vite | 4.3.3 | 見た目をクラスで書く（配色は `@theme` で決める） |
| codemirror | 6.0.2 | SQL エディタ |
| @codemirror/lang-sql | 6.10.0 | SQL の色分けと補完（方言は `PostgreSQL`） |
| @codemirror/lint | 6.9.7 | エラーの位置の波線（`setDiagnostics`）。`codemirror` が引く版と同じにして、二重に読み込まない |
| @electric-sql/pglite | 0.5.8 | ブラウザ内の PostgreSQL 18.3 |
| Vitest | 5.0.0 | 採点ロジックと模範解答の自動検査のテスト（設定は Astro の `getViteConfig` で共有する） |
| @astrojs/check、TypeScript | 0.9.10、6.0.3 | 型検査（`astro check`） |
| pnpm | 10.34.5 | パッケージ管理（`package.json` の `packageManager` で固定する） |

- PGlite は 0.x でマイナー版の更新でも互換性が壊れうるので、`package.json` で版を完全に固定する。
- Astro 7 は Node.js 22.12.0 以上を要求する。CI は Node.js 24 で動かす。
- 開発者の pnpm の設定（公開から 21 日たっていない版を入れない）を満たす版を選んだ。Astro は調査時点の最新の 7.3.5 ではなく 7.3.2 である。
- TypeScript を 7 にしないのは、`@astrojs/check` 0.9.10 が TypeScript 5 と 6 にしか対応していないからである。
- リンターとフォーマッターは入れない。開発者が 1 人のあいだは、型検査で足りる。
- React などの UI フレームワークと MDX は使わない。画面の動きは Astro が束ねる素の TypeScript で書く。MDX は本文中の `<` と `{` のエスケープを要求し、比較演算子を説明するレッスンと相性が悪い。
- 見た目は Tailwind CSS のクラスで書く。
  `src/styles/global.css` に `@import "tailwindcss";`、配色の `@theme`、Markdown の本文の見た目を戻す `@layer base` を置き、全ページが読み込む。
- Tailwind の preflight はブラウザ既定の見た目を消すので、クラスを書けない Markdown の本文の要素（段落、見出し、リスト、リンク、コード、表）は `@layer base` で整える。
  `@tailwindcss/typography` は使わない。
  独自の配色と文字の大きさを持っていて、配色に合わせて上書きする手間がかかるからである。
- CodeMirror の外枠（`.cm-editor`）には、`EditorView.editorAttributes` でクラスを付ける。
  内側の要素（`.cm-scroller` など）にはクラスを付けられないので、演習のエディタの高さは、演習の要素に `[&_.cm-scroller]:min-h-[5.5em]` を付けて整える。
  エディタの中の書体は CodeMirror が `monospace` に決めていて、サイトの書体の指定は効かない。
- `astro.config.mjs` には `site`（`https://ccc-k-fujimura.github.io`）、`base`（`/learn-sql-from-browser`）、`vite.optimizeDeps.exclude: ['@electric-sql/pglite']` を書く。公開 URL は `https://ccc-k-fujimura.github.io/learn-sql-from-browser/` になる。
- 同じファイルに `vite.plugins: [tailwindcss()]`、`vite.worker.format: 'es'`、`markdown.syntaxHighlight: false` も書く。
  1 つ目は、Tailwind CSS を Vite のプラグインとして動かすためである。
  2 つ目は、PGlite が中で動的 import を使うので、Worker を ES モジュールとして出力するためである。
  3 つ目は、`sql` のコードブロックをエディタに置き換えるのでビルド時の色分けが要らず、切ると `<pre><code class="language-sql">` という探しやすい形で出力されるからである。
- 本文中のリンクは相対パスで書くか、テンプレートで `base` を付けて生成する。絶対パスのリンクには `base` が付かず、GitHub Pages で切れる。
- 公開は GitHub Actions で行う。`withastro/action@v6` がビルドと成果物のアップロードを、`actions/deploy-pages@v5` が公開を行う。権限に `pages: write` と `id-token: write` を与え、リポジトリの Pages の設定で Source に GitHub Actions を選ぶ。
- ワークフロー（`.github/workflows/ci.yml`）は、型検査とテスト、ビルド、公開の順に進む。PR では公開の手前のビルドまでを行い、main への push でだけ公開する。
- PGlite は、`sql` のコードブロックか演習があるページでだけ動的 import で読み込む。トップページやレベルのページには JavaScript をほぼ出さない。

ページを移るたびに PGlite を初期化し直すことになる（Chrome で約 1.3〜2 秒、Firefox で約 4 秒）。
初回の転送量は約 5.6 MB で、2 回目以降はブラウザのキャッシュが効く。

## DB の実行

PGlite は Web Worker の中で動かす。
メインスレッドを止めないためと、終わらない SQL を Worker ごと捨てて止めるためである。

- **起動**：`PGlite.create()` で作る。タイムゾーンはリセットのたびに設定する。
- **リセット**：学習者の SQL を実行する直前に毎回、`ROLLBACK; RESET ALL; DISCARD TEMP; SET TimeZone = 'Asia/Tokyo'; DROP SCHEMA IF EXISTS public CASCADE; CREATE SCHEMA public;` と題材データの SQL を流す。先頭の `ROLLBACK` は、学習者が `BEGIN` を残した場合に備えるものである。`RESET ALL` は `SET search_path` のようなセッションの設定を戻し、`DISCARD TEMP` は `books` と同じ名前の一時テーブルを消す。`DISCARD ALL` は複数の文の中では実行できないので使わない。`IF EXISTS` は、学習者が `public` スキーマを消した場合に備えるものである。`BEGIN` と `ROLLBACK` で包む方法は、学習者の `COMMIT` で確定してしまううえシーケンスも戻らないので採らない。`public` 以外に学習者が作ったスキーマは残るが、`SELECT` だけを扱う入門では困らない。
- **実行**：`exec(sql, { rowMode: 'array', parsers })` で実行する。`query()` は複数の文を受け付けない。既定の `rowMode` では同じ名前の列が 1 つに潰れる。
- **値の受け取り**：`parsers` には、主な型の OID（16、20、21、23、25、700、701、1043、1082、1083、1114、1184、1700）に恒等関数を渡し、値を PostgreSQL の文字列表現のまま受け取る。
- **採点に使う結果**：`exec()` が返す配列の最後の要素を使う。`fields` が空なら「結果の表がない」と扱う。
- **エラー**：例外の `message`、`code`（SQLSTATE）、`position`（1 始まりの文字位置で、渡した SQL 全体の先頭から数える）、`hint` を取り出す。クラス名は本番ビルドで短縮されるので、判定には `code` の有無を使う。
- **止める操作**：実行が 1 秒を超えたら、ボタンの横に「時間がかかっています…」と「止める」を出す。押すか 10 秒たつと Worker を `terminate()` し、新しい Worker を作り直す（試作では約 2 秒、ヘッドレス Chrome で約 2.3 秒）。数える時間は、依頼を Worker に渡してからで、起動や作り直しを待つあいだは数えない。
  - 止めた実行は、結果の代わりに「実行を止めました。」と出す。10 秒の時間切れになった実行だけは「10 秒たっても終わらなかったので、実行を止めました。」と出す。止めたことは演習の間違いに数えず、模範解答は開けない。
  - Worker は実行を 1 つずつ処理するので、ほかの例や演習の実行が前に詰まっているときは、後ろに並んだ実行にも「止める」が出る。止めると、並んでいた実行もまとめて止まり、「実行を止めました。」と出る。作り直しの途中で重ねて止めても、Worker は増やさない。
  - 作り直しのあいだに押された実行は、新しい Worker の起動を待ってから実行する。
- **準備中の表示**：DB の起動中と作り直し中は、画面上部の帯で「データベースを準備しています…」と知らせる。

参考実装は [prototypes/lesson-screen/db-worker.js](../.scratch/sql-learning-site/prototypes/lesson-screen/db-worker.js) と [db.js](../.scratch/sql-learning-site/prototypes/lesson-screen/db.js) にある。

## 採点

演習は、学習者の SQL の結果の表と期待結果を比べて採点する。
期待結果は、模範解答を同じ DB でその場で実行して作る。
SQL の文面は見ない。

比べる順序と、間違えたときに出す判定の文は次のとおりである。

1. **列の数**：違えば「列の数が違います。期待する結果は 2 列ですが、あなたの結果は 3 列です。」
2. **列の並び**：列名の集まりが同じで並びだけ違えば「列の並びが違います。title、price の順に並べてください。」
3. **列名**：`checkNames: true` の演習でだけ比べる。違えば「2 列目の名前が違います。「税込価格」という名前を付けてください（いまは「?column?」）。」
4. **行**：同じ行が何回出たかまで含めて比べる（DISTINCT の書き忘れを正解にしないため）。違えば「足りない行が 2 行あります。」「余分な行が 1 行あります。」
5. **行の順序**：`ordered: true` の演習でだけ比べる。違えば「行はそろっていますが、並び順が違います。」

結果の表がなければ「結果の表がありません。SELECT 文を書いて実行してください。」と出す。
すべて一致すれば正解である。

- **値の比べ方**：数値の型（OID 20、21、23、700、701、1700）どうしは数値として比べ、`1650.0` と `1650.00` を同じとみなす。それ以外は文字列表現で比べる。NULL と空文字は区別する。
- **複数の文**：最後の文の結果を採点する。
- **模範解答の露出**：模範解答はページのソースから読めるが、許容する。ランキングや修了証がなく、のぞいて得をする人がいないからである。

演習を作る側は次の 2 点を守る。

- 絞り込みの演習（WHERE や LIMIT を使うもの）では、期待結果を 0 行にも全行にもしない。0 行なら `WHERE false` が、全行なら WHERE の書き忘れが正解になってしまう。
- 順序を比べる演習では、並びが 1 通りに決まるよう、2 番目の並べ替えの条件（`title_kana` や `id`）を問題文で指定する。

参考実装は [prototypes/lesson-screen/grade.js](../.scratch/sql-learning-site/prototypes/lesson-screen/grade.js) にある。

## レッスン画面

1 レッスンを 1 ページの縦一列で見せる。

- **並び**：パンくず、レッスン名、`books` テーブルの列の表（列名、意味、値の例）、本文（説明と例）、演習、前後のレッスンへのリンクの順に並べる。
- **例**：本文の `sql` のコードブロックを、エディタと「実行」ボタンに置き換える。結果の表を下に出し、採点はしない。
- **演習**：問題文、空のエディタ、「実行して答え合わせ」ボタン（Ctrl + Enter でも実行できる）を置く。期待結果の表は先に見せない。
- **正解したとき**：判定の文を緑の帯で出し、結果の表を見せる。
- **間違えたとき**：判定の文を赤の帯で出し、自分の結果の表（見出しは「あなたの結果」）で余分な行を赤くする。余分な行があるときは表の先頭に列を足し、余分な行に「余分」と書く。足りない行は「足りない行」として黄色の別の表で見せる。
- **ヒント**：いつでも 1 つずつ開ける。「ヒント 1 を見る」のボタンを押すたびに次のヒントを出し、全部出したらボタンを消す。
- **模範解答**：答え合わせで 1 回間違えたら開ける。SQL のエラーも間違いに数え、空のまま実行したときは数えない。一度開けるようになったら、正解したあとも開ける。
- **リセット**：実行のたびに DB が初期状態に戻るので、ボタンは置かない。
- **NULL**：結果の表では灰色の斜体で `NULL` と書き、空文字と見分けられるようにする。
- **エディタ**：CodeMirror 6 を `basicSetup` と `sql({ dialect: PostgreSQL, schema, defaultTable, upperCaseKeywords: true })` で使う。`schema` に `books` の列を渡して補完に使う。`defaultTable` に `books` を渡さないと、列名は `books.` の後ろでしか補完されない。Windows の Chrome と Edge で、既定の設定のまま日本語入力に問題がないことを確かめた。

エラーは日本語の説明を先に出し、英語の元のメッセージは折りたたむ。
`position` があれば、エディタ上のその位置から語の終わりまでに波線を引く。
日本語の説明を用意するエラーは次のとおりで、それ以外は汎用の説明を出す。

| SQLSTATE | 場面 | 説明 |
|---|---|---|
| 42601 | 構文の誤り | SQL の書き方に誤りがあります。印の付いた位置の近くで、カンマの付けすぎや付け忘れ、キーワードのつづりを確認してください。 |
| 42601（`unterminated quoted string`） | 引用符の閉じ忘れ | シングルクォート（'）が閉じていません。文字列の終わりにもシングルクォートを付けます。 |
| 42703 | 存在しない列 | 指定した列がありません。列名のつづりを確認してください。文字列をダブルクォート（"）で囲んでいませんか？ 文字列はシングルクォート（'）で囲みます。 |
| 42P01 | 存在しないテーブル | 指定したテーブルがありません。このレッスンで使うテーブルは books です。 |
| 22P02 | 数値でない値との比較 | 数値の列を、数値ではない値と比べています。数値は引用符で囲まずに書きます。 |
| 22007 | 日付の書き方 | 日付の書き方に誤りがあります。日付は '2024-01-01' の形で書きます。 |
| 22008 | 存在しない日付 | 存在しない日付です。日付は '2024-01-01' の形で書き、月と日の値を確認してください。 |
| 42883 | 型の合わない比較や計算 | この組み合わせでは、比べたり計算したりできません。文字列の列と数値を比べていないか確認してください。 |
| 42804 | 条件になっていない WHERE | 条件の書き方に誤りがあります。WHERE の後ろには「price >= 1000」のような条件を書きます。 |
| 22012 | 0 での割り算 | 0 で割ることはできません。 |
| その他 | | エラーが起きました。下の英語のメッセージと、印の付いた位置を手がかりに確認してください。 |

試作は [prototypes/lesson-screen](../.scratch/sql-learning-site/prototypes/lesson-screen/) にあり、`npm install` と `npm run dev` で起動する（案 A が採用した画面である）。

## サイトの構成

| ページ | URL | 置くもの |
|---|---|---|
| トップ | `/` | サイト名、一文の紹介、「続きから」ボタン、4 レベルのカード（2×2） |
| レベル | `/intro/` | レベルの説明、修了数と進捗バー、「続きから」ボタン、レッスン一覧 |
| レッスン | `/intro/<名前>/` | 「レッスン画面」の節のとおり |
| 修了 | `/intro/complete/` | 入門を修了したこと、初級が準備中であること、総まとめの解き直しの勧め |

- **レベルのカード**：境界の 1 行、レッスン数と所要時間、修了数と進捗バーを載せる。準備中のレベルは灰色のカードに「準備中」と境界の 1 行を添える。実践応用のカードには「自分の PC に用意した環境で取り組みます」と書く。
- **レッスン一覧**：番号、レッスン名、到達目標、進捗の印（未着手、途中、修了）を並べる。
- **レッスンのページ**：先頭にパンくず（トップ › 入門）、末尾に「前のレッスン、レッスン一覧へ、次のレッスン」を置く。総まとめの「次」は修了のページに進む。
- **続きから**：修了していない最初のレッスンに飛ぶ。1 本も手を付けていなければ「最初のレッスンから始める」と表示する。
- **進捗**：レッスンの演習に全問正解したら修了、1 問以上正解したら途中とする。答えを開いたかどうかは問わない。
- **進捗の保存**：localStorage のキー `browser-sql:progress` に、レッスンごとの正解した演習の番号を JSON で保存する（例：`{"intro/where": [0, 2]}`）。GitHub Pages では同じ所有者のサイトが origin を共有するので、キーにサイト固有の接頭辞を付ける。レッスンはファイル名の番号ではなく名前で識別するので、レッスンを足しても保存済みの進捗はずれない。演習の並びを入れ替えると進捗がずれるので、公開後に演習を入れ替えるときは注意する。
  localStorage が使えないとき（プライベートウィンドウや保存の拒否）は、進捗を空として扱い、保存もしない。
  画面はすべて未着手で出し、答え合わせはそのままできる。

試作は [prototypes/site-skeleton/index.html](../.scratch/sql-learning-site/prototypes/site-skeleton/index.html) にある（案 B が採用した構成である）。

出典：[サイトの骨組み](../.scratch/sql-learning-site/issues/08-site-skeleton-prototype.md)

- 進捗バーには、修了数を文字で添える。
  残りの部分（`progress-track`）は背景に対して 1.45:1 で、バーの全体の長さを色だけでは読み取りにくい。
- ダークモードには対応しない。
  エディタ（CodeMirror）のテーマも切り替える必要があり、入門編の範囲を超える。

## レッスンファイルの書式

ファイルは次のように置く。

```text
src/
  levels.ts                  4 レベルの名前、境界の 1 行、公開済みか、列の表の中身
  data/intro/seed.sql        入門の題材データ（CREATE TABLE と INSERT）
  content/lessons/intro/
    01-first-select.md
    02-columns.md
    ...
    10-review.md
docs/
  writing-lessons.md         執筆ガイド
```

1 レッスンは、frontmatter（YAML）と Markdown の本文からなる 1 つの `.md` ファイルで書く。

````markdown
---
title: 条件で行を絞る
goal: 数値や文字列の条件に合う行だけを取り出せる
exercises:
  - prompt: 価格が 1000 円以上の本の、書名と価格を表示してください。
    answer: |
      SELECT title, price
      FROM books
      WHERE price >= 1000;
    hints:
      - 「以上」は >= で表します。
      - 1000 円ちょうどの本も含みます。
  - prompt: 技術書の書名と価格を、価格の高い順に表示してください。価格が同じなら id の小さい順にします。
    answer: |
      SELECT title, price
      FROM books
      WHERE genre = '技術書'
      ORDER BY price DESC, id;
    ordered: true
    hints:
      - ORDER BY price DESC で高い順になります。
---

これまでは、テーブルのすべての行を表示してきました。
`WHERE` を使うと、条件に合う行だけを取り出せます。

```sql
SELECT title, price
FROM books
WHERE price < 500;
```

条件は次の形で書きます。

```text
SELECT 列名 FROM テーブル名 WHERE 条件;
```
````

frontmatter の項目は次のとおりで、content collection のスキーマでビルド時に検証する。

| 項目 | 意味 | 型 | 省略したとき |
|---|---|---|---|
| `title` | レッスン名 | 文字列 | 省略できない |
| `goal` | 到達目標 | 文字列 | 省略できない |
| `exercises` | 演習の並び | 配列（1 問以上） | 省略できない |
| `exercises[].prompt` | 問題文 | 文字列 | 省略できない |
| `exercises[].answer` | 模範解答 | 文字列 | 省略できない |
| `exercises[].hints` | ヒントの並び | 文字列の配列 | 省略できない |
| `exercises[].ordered` | 行の順序を比べる | 真偽値 | 比べない |
| `exercises[].checkNames` | 列名を比べる | 真偽値 | 比べない |

- **本文**：学習者向けの敬体（「です」「ます」で終える文体）で書く。言語名 `sql` のコードブロックはその場で実行できる例になり、`text` は表示だけになる。エラーを見せたい間違った SQL も `sql` で書く。コードブロックの言語名のあとに書いた語は HTML に残らないので、区別には使えない。
- **演習**：本文の後ろにテンプレートが並べる。
- **問題文とヒント**：Markdown として解釈せず、そのままの文字列として表示する。
- **並び順と URL**：並び順はファイル名の番号で決め、URL と進捗の識別には番号を除いた名前を使う（`03-where.md` は `/intro/where/`）。
- **列の表**：`src/levels.ts` から作るので、レッスンファイルには書かない。

出典：[レッスンファイルの書式](../.scratch/sql-learning-site/issues/09-lesson-file-format.md)

## 模範解答の自動検査

公開の前に GitHub Actions で、全レッスンの全演習の模範解答を、そのレベルの題材データに対して Node 上の PGlite で実行する。
次のどれかに当たれば、ビルドを止める。

- 実行するとエラーになる。
- 結果の表がない（最後の文が SELECT ではない）。
  レッスン画面は、期待結果があることを前提にしている。
- 結果が 0 行になる。
- WHERE か LIMIT を含むのに、結果が `books` の全行になる。
- `ordered: true` なのに、模範解答に ORDER BY がない。

並びが 1 通りに決まるかは機械では判定しにくいので、人のレビューで確かめる。

検査は `src/answers.test.ts` にあり、CI の `pnpm test` で走る（失敗すると、後ろのビルドと公開も止まる）。
テスト名は「模範解答：intro/01-first-select.md の演習 1」のようになり、どのレッスンのどの演習かがわかる。
WHERE、LIMIT、ORDER BY は、模範解答の最後の文から、文字列、引用符で囲んだ名前、コメントを除いて探す。
採点に使うのも、最後の文の結果である。
WHERE と LIMIT は副問い合わせの中も数え、ORDER BY は外側の文（括弧の外）だけを見る。
副問い合わせの中の ORDER BY や `OVER (ORDER BY …)` は、結果の並びを決めないからである。
選択リストの相関副問い合わせにだけ WHERE がある模範解答は、全行なら誤りとされる。
この誤検出ではビルドが止まるので、人が気づく。

出典：[レッスンファイルの書式](../.scratch/sql-learning-site/issues/09-lesson-file-format.md)

## 執筆ガイド

`docs/writing-lessons.md` に、Claude がレッスンを下書きし、人がレビューするときに参照する決まりを 1 か所にまとめる。

- frontmatter の項目名と意味の対応表（「レッスンファイルの書式」の節）。
- 本文の文体（学習者向けの敬体（「です」「ます」で終える文体））。
- SQL の書き方の流儀（「入門カリキュラム」の節）。
- 演習を作るときの決まり（「採点」の節の末尾の 2 点）。
- 題材データの決まり（「題材データ」の節の条件）。
